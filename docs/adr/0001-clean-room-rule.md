# Clean-room rule: learn by observation, write every line fresh

The G15C firmware interface is unknown, and on 2026-10-12 we set how we may learn it, following Asahi Linux's long-standing practice and, since 2026-10-13, the Aurora Silicon team's own method. **Allowed:** learning facts by observation: hardware behaviour, firmware messages and logs, the Mac's own device tree, measurements on Linux, and tracing a macOS 14.8.3 guest under m1n1 on Naeem's own Mac (the installer and the guest kernel stay private, never published or pushed). **Never in our code:** copied expression of any kind: Apple code, Apple binaries, private-tree code, copied comments or tables. Facts (offsets, encodings, message sequences, symbol names a trace shows) are fine; every line we commit is written fresh from them. Firmware crash logs are read on the M3 only, decoded only as far as Linux's own RTKit crash-log parser documents the sections, and never published. Trial values must have a known origin (seen working on another Apple GPU or firmware), one per boot, with a stated reason. Per-device data (security identities, calibration, volume-group IDs) never leaves the Mac. Decided in malik-na/linux-aurora#12; aligned with the team method in #15's thread.

## Consequences

- Provenance of each firmware interface value is recorded in our fact records (this branch), not in public commit text; commit messages cite public sources, device-tree paths and Linux measurements only.
- Before any omacom PR: trailers become `Assisted-by: LLM` then `Signed-off-by`; commit text, PR text and linked notes pass the team's keyword scan; static gates (`git diff --check`, checkpatch, W=1, dtbs_check, KUnit) and one clean boot per change.
- Order of sources for the G15C firmware interface: the device-control test boot, the team, the crash log's documented sections, then the macOS 14.8.3 trace (moved up by Naeem on 2026-10-12).
